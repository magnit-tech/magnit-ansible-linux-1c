# Ansible

Этот репозиторий содержит набор Ansible-ролей для автоматизации установки, настройки и управления серверами 1С:Предприятие, а также интеграции с дополнительными инструментами, такими как Vector, OpenSearch и ClickHouse.

---

## Подготовка к работе

1. **Проверка установки Ansible**

Убедитесь, что Ansible установлен на компьютере, с которого он будет запускаться. Проверьте версию командой:
```bash
sudo ansible --version
```

2. **Копирование каталога Ansible**

Скопируйте каталог `ansible` в требуемое место (по умолчанию — в корень). В конфигурационном файле `ansible.cfg` при необходимости измените значение ключа `inventory` на каталог, куда скопирован `ansible`.

3. **Подготовка файла `hosts`**

Подготовьте файл `hosts` — список хостов и их групп. Все хосты нужно разбить по группам в зависимости от того, какие роли на них должны выполняться.

4. **Настройка файла `side.yml`**

По умолчанию в файле `side.yml` содержатся роли для установки сервера 1С "с нуля". При необходимости файл можно отредактировать. Пример использования всех ролей приведен в файле `side_ALL.yml`.

Установите требуемую версию 1С в переменной `onec_version_name`. При необходимости отредактируйте другие переменные. Скопируйте инсталляционный файл 1С в каталог, который определен в переменной `ins_dir_src`.

5. **Пользователь для выполнения задач**

Пропишите пользователя, под которым будет запускаться Ansible, в групповых переменных в папке `group_vars`. Имя файла должно соответствовать имени группы хостов. Обязательно заполните переменную `ansible_user`. Иначе её придется прописывать в строке запуска. Пользователь текущего компьютера должен совпадать с пользователями на хостах.

6. **Запуск основного плейбука**

Запустите основной плейбук из каталога `ansible` командой:
```bash
ansible-playbook -i hosts side.yml -K
```
Если возникает ошибка:
`Using a SSH password instead of a key is not possible because Host Key checking is enabled and sshpass does not support this. Please add this host's fingerprint to your known_hosts file to manage this host.`,

выполните команду без `sudo`:
```bash
export ANSIBLE_HOST_KEY_CHECKING=False
```
Если возникает ошибка: `"Failed to connect to the host via ssh: ivanov_ii@x.x.x.x: Permission denied (publickey,gssapi-keyex,gssapi-with-mic,password)."`

проверь указал ли ты верно переменные `ansible_user=ivanov_ii` и `ansible_password=xxx` в inventory файле или в group_vars/<Группа>,
альтернативный вариант запускать от имени схожего пользователя ivanov_ii и использовать флаг --ask-pass
```bash
ansible-playbook -i hosts side.yml -K --ask-pass
```

Иначе проверь возможность входа на целевой сервер по ssh -p 22 ivanov_ii@x.x.x.x

Если пошли другие ошибки есть флаг отладки -vvv
```bash
ansible -i hosts <Группа / all> -m ping -K --vvv --ask-pass
```

## Основные плейбуки

### `side.yml`

Основной плейбук — `side_ALL.yml`. Он запускается первым, а уже из него вызываются другие плейбуки ролей. В нем можно переопределить, какие роли должны выполняться на каких группах хостов или отдельных хостах.

Здесь заданы общие переменные, например:

- `onec_version_name` — устанавливаемая версия 1С.
- Другие переменные, которые можно переопределить, если требуются значения, отличные от значений по умолчанию (в файлах ролей по путям `.../Имя роли/defaults/main.yml`).

Настроено два сценария, которые предполагается выполнять на разных группах серверов:

- Установка сервера приложения.
- Установка веб-сервера и публикация баз.

Эти сценарии разделены для возможности установки дополнительного сервера приложения 1С на другом порту (например, с отладкой и без отладки) и публикации на одном сервере нескольких баз. В данный момент решение таких задач реализовано с помощью создания различных групп хостов, в которые входят одни и те же хосты.

В сценариях установки сервера приложения 1С можно переопределить следующие переменные (которые по умолчанию заданы в папках `defaults` соответствующих ролей):

- `SRV1CV8_DEBUG`: признак необходимости запуска сервера отладки. По умолчанию отладка отключена.
- `SRV1CV8_PORT`: Порт запуска `ragent`. По умолчанию — `1540`.
- `SRV1CV8_REGPORT`: Порт запуска `rmngr`. По умолчанию — `1541`.
- `SRV1CV8_RANGE`: Диапазон портов рабочих процессов. По умолчанию — `1560:1591`.
- `RAS_PORT`: Порт сервера администрирования. Если не задан, то служба не будет установлена. По умолчанию — `1539`.

Эти переменные будут действовать на все хосты соответствующей группы сценария.

### `siderev2.yml`

Плейбук `siderev2.yml` предназначен для запуска функции реструктуризации v2. При необходимости включения данной функции запускается после отработки основного плейбука. При необходимости файл можно отредактировать, как и другие переменные в нем. Перед запуском скопируйте инсталляционный deb-пакет JRE в каталог, который определен в переменной `install_JRE`.

Запуск плейбука выполняется из каталога `ansible` командой:

```bash
ansible-playbook -i hosts siderev2.yml -K
```

## Инвентарный файл `hosts`

Файл `hosts` позволяет распределять хосты по группам и переопределять переменные для отдельных хостов. Здесь определены настройки публикаций баз 1С на веб-серверах. При необходимости можно переопределить и переменные для установки сервера 1С:Предприятие, например `SRV1CV8_DEBUG` — признак отладки на сервере.

Часть переменных можно определить для всей группы хостов. Это можно сделать в файле с именем группы, расположенном в папке `group_vars`.

Пример файла `hosts`:

```ini
[serv1C]
some_host_url ansible_host=some_host_ip ansible_user=ivanov_ii


```

## Роли

В данной сборке используется ряд ролей:

### 1. **install\_deb\_packages**

Устанавливает скачанные ранее deb-пакеты. Используется для установки Apache или дополнительных пакетов шрифтов для 1С (`fontconfig`).

### 2. **first\_setup**

Первоначальная настройка перед установкой платформы сервера 1С:Предприятие. Выполняет следующие действия:

- Копирование шрифтов из папки `./fonts` в `/usr/share/fonts`.
- Создание группы пользователей `grp1cv8` и пользователя `usr1cv8`.
- Создание каталогов для размещения программных файлов, специальных каталогов 1С и временных каталогов для инсталляционных файлов.
- Копирование требуемых шрифтов.

### 3. **install\_1C**

Устанавливает платформу требуемой версии сервера 1С:Предприятие. Выполняет следующие действия:

- Останавливает и удаляет службы старых версий 1С (если переменная `flag_Remove_old_1C_service` равна `true`).
- Копирует файл единого дистрибутива (например, `setup-full-8.3.21.1393-x86_64.run`) из папки `ins_dir_src/inst_file_name` в папку хоста `ins_dir_dest`.
- Устанавливает серверные компоненты платформы. Требуемые компоненты для установки определяются переменной `enable_components` (по умолчанию — серверные компоненты). В сценарии установки веб-сервера эта переменная переопределяется для установки только компонента `ws`.

### 4. **install\_ragent**

Устанавливает службу сервера 1С. Выполняет следующие действия:

- Подготавливает файл настройки служб по требуемым параметрам (порты, пути к служебным директориям, необходимость и вид отладки и т.д., определенными переменными `SRV1CV8_PORT`, `SRV1CV8_REGPORT`, `SRV1CV8_RANGE`, `SRV1CV8_DEBUG`).
- Создает символьную ссылку на файл.
- Создает и запускает службы `ragent`, `rmngr`, `rphost`, `dbgs`.

### 5. **install\_ras**

Устанавливает службу RAS. Выполняет следующие действия:

- Подготавливает файл настройки службы сервера удаленного администрирования по требуемым параметрам (порты `ras`, `ragent`, определенными переменными `RAS_PORT`, `SRV1CV8_PORT`).
- Создает символьную ссылку на файл.
- Создает и запускает службу `ras`.

### 6. **setup\_apache**

Настраивает Apache после его установки:

- Копирование конфигурационных файлов.
- Копирование файлов сертификатов (файлы `cert.key` и `cert.cer` должны быть заранее получены и размещены в каталоге `setup_apache/files/`).
- Включение модулей для работы с SSL.

### 7. **restart\_apache**

Перезапускает службу Apache.

### 8. **publishing**

Публикует базу 1С, её веб-сервисы и HTTP-сервисы. Переменные для публикации уникальны для хостов и прописаны в инвентарном файле `hosts`.

### 9. **monitoring\_1C**

Устанавливает необходимые пакеты и добавляет в CRON задание для выполнения скрипта `zabbix_exporter.py` каждые 30 секунд.

### 10. **install\_JRE**

Устанавливает пакет JRE перед включением функции реструктуризации v2. Необходимо создать директорию по пути, указанному в переменной `install_JRE` файла `siderev2.yml`, и скопировать туда deb-пакет перед запуском роли.

### 11. **enable\_rv2**

Роль для включения функции реструктуризации v2.
**Внимание!** Если после успешной отработки данной роли необходимо запускать другие плейбуки, выполните следующие действия:

1. Перейдите в каталог `/etc/`.
2. Откройте файл `environment` командой:
```bash
sudo nano environment
```
3. Закомментируйте строку `PATH=$PATH:$JAVA_HOME/bin`, чтобы она приобрела вид:
```bash
#PATH=$PATH:$JAVA_HOME/bin
```
4. После завершения работы с плейбуками раскомментируйте строку.

### 12. **versioning\_linux\_configs**

Устанавливает пакеты для синхронизации конфигурационных файлов с GitLab.

### 13. **install\_lictools**

Устанавливает инструменты лицензирования 1С (ring license).

### 14. **install\_vector4opensearch**

Устанавливает и настраивает Vector для отправки логов 1С в OpenSearch:

- Копирует файл `logcfg.xml` в `/opt/1cv8/conf` с динамической подстановкой имени хоста.
- Устанавливает владельца и группу для каталога `/var/1C`.
- Устанавливает права `755` для каталога `/var/1C` и всех вложенных файлов/каталогов.
- Копирует скрипт `remove_racdirs_only.py` в `/opt/1cv8/scripts` и добавляет задание в CRON для его выполнения каждую минуту.

### 15. **deploy_configure_keytabs**

Разворачивает файлы keytab на сервера и устанавливает права доступа:

- Проверка на существование директории `/opt/1cv8/conf` (создание, если нет).
- Копирование keytab файла на удаленный сервер с правами.
- Проверка наличия условий в keytab файле.
- Инициализация тикета Kerberos, используя keytab файл.
- Собираем логи результата kinit.

### 16. **connect_disconnect_infobase**

Подключает/отключает информационную базу с помощью предустановленной на сервере утилиты 1C - rac (Remote Administrative Client):
- Извлекает cluster UUID.
- Производит получение infobase UUID (если отключаем).
- Подключает информационную базу (если подключаем).
- Отключает информационную базу (если отключаем).

### 17. **actualize_scripts_with_pass_util**

Актуализирует скрипты zabbix_exporter.py (Мониторинг 1C), versioning_configs.py (Синхронизация конфигов 1C с GitLab) с учетом утилиты PASS:
- Устанавливает утилиту PASS.
- Копирует скрипты zabbix_exporter.py, versioning_configs.py.
- Копирует '.password-store' в /tmp.
- Разархивируюет '.password-store' в домашнюю директорию пользователя.
- Копирует открытый ключ в /tmp.
- Устанавливает приватный ключ пользоваетлю.
- Удаляет '.password-store' и приватный ключ из /tmp.
- Добавляет/изменяет задачи на запуск Мониторига 1C, Синхронизации 1C Linux конфигов с GitLab.
- Еще раз чистит /tmp от паролей на всякий случай.

### 18. **mount_dirs**

Монтирует необходимые каталоги на сервере.
Основные параметры:
- fs_type - Тип файловой системы
- vg_name - Имя группы логических томов
- disk_device - Имя диска над которым будет проводить работы
- lvm_structure - Список каталогов которые надо смонитровать
- lvm_structure.name - Имя логического тома
- lvm_structure.size - Размер логического тома
- lvm_structure.mount - Точка монтирования
- lvm_structure.migrate - Флаг отвечает за миграцию данных
- lvm_structure.create_dir - Флаг отвечат за создание папки

## Другие плейбуки:

### side_install_docker

- Удаляет старые версии Docker.
- Устанавливает Docker и Docker Compose.
- Создает группу `docker` и добавляет текущего пользователя в эту группу.

### side_connect_test_IB

- Подключает/отключает тестовую информационную базу с помощью установленной на сервере rac (Remote Administrative Client).
- Настраивает доменную аутентификацию (копирует файлы keytab на сервер и устанавливает права доступа).

## Особенности работы

1. Скопируйте каталог `ansible` на свой компьютер (например, в корень).
2. Переопределите переменные, описанные выше.
3. Пользователь на хостах должен совпадать с пользователем на компьютере, с которого выполняется установка. Пароль также должен быть одинаковым.
4. Если нет необходимости выполнять определенную роль, её можно закомментировать в файле `side.yml`. Например, при установке новой версии платформы 1С на хосты, где уже есть старая версия, можно отключить роль `first_setup`.
5. Если требуется установить несколько служб приложения сервера 1С на один хост, заполните переменные для второй службы и закомментируйте все роли, кроме `install_ragent`.
6. Аналогичный подход можно использовать для публикации дополнительных баз 1С на веб-сервере.
7. Настройте список хостов в файле `hosts`.
8. Запуск основного плейбука выполняется из каталога `ansible` командой:
```bash
ansible-playbook -i hosts side.yml -K
```

Параметр `-K` указывает на выполнение некоторых задач под `sudo` и требует ввода пароля.
